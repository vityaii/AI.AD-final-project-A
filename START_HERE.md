# Проверка проекта

Автор: Никитин Виктор. Группа: КультИИ АД Мод 3 1.3.
Учебная БД учёта задач: 8 пользователей, 4 проекта, 16 этапов, 120 задач.
Все данные синтетические.

## 1. Распакуйте проект

Извлеките ZIP целиком: Windows — «Извлечь всё», macOS — двойной щелчок,
Linux — файловый менеджер. Не запускайте файлы из окна просмотра архива.
Откройте терминал в папке, где находятся README.md и папки sql, python, data.
Сохраняйте структуру папок.

## 2. Установите зависимости

Нужны запущенный PostgreSQL 17+ и Python 3.11+.
В командах ниже `python` — команда вашего Python; на macOS/Linux это обычно `python3`.

```sh
python -m venv .venv
```

Активируйте окружение:

- Windows PowerShell: `.venv\Scripts\Activate.ps1`.
- Windows cmd: `.venv\Scripts\activate.bat`.
- macOS/Linux: `source .venv/bin/activate`.

Если PowerShell запрещает активацию, используйте cmd либо запускайте команды
через `.venv\Scripts\python.exe` вместо `python`; менять системные политики не требуется.
После активации:

```sh
python -m pip install -r python/requirements.txt
```

## 3. Запустите проверку

```sh
python python/verify_project.py --host localhost --port 5432 --user postgres
```

Подставьте пользователя своего PostgreSQL. Пароль запрашивается скрыто и не сохраняется.
Для подключения без пароля нажмите Enter. Скрипт не устанавливает и не запускает сервер PostgreSQL.
Пользователю нужно право создавать БД (CREATEDB); служебная БД по умолчанию — postgres.

Скрипт создаёт новую БД с уникальным именем, выполняет schema.sql → seed.sql → checks.sql → queries.sql,
сверяет строки таблиц с CSV и результаты восьми запросов с эталоном, затем строит графики.
Существующие БД не очищаются и не перезаписываются. Для повторной проверки достаточно повторить команду.
Созданные учебные БД остаются на сервере для просмотра в pgAdmin.

При успехе выводится «Проверка завершена успешно», а в папке verification появляются:

- summary.md — итог PASS и выполненные проверки;
- sql_log.txt — результаты выполнения SQL и проверки ограничений;
- queries — восемь CSV с результатами;
- charts — три графика в PNG и SVG.

Готовые эталонные результаты в папке results не меняются.

| Проверка | Ожидается |
|---|---:|
| Пользователи / проекты / этапы / задачи | 8 / 4 / 16 / 120 |
| Задачи по проектам | 54 / 38 / 28 / 0 |
| Завершённые / активные | 46 / 74 |
| Просроченные активные с известным сроком | 26 |

Если подключение не удалось, проверьте запуск PostgreSQL, порт, пользователя и пароль.
Если нет права CREATEDB, используйте другого пользователя либо ручной способ ниже.
При ошибке скрипт завершится с ненулевым кодом и запишет FAIL в summary.md.

## 4. Проверка SQL вручную

В pgAdmin создайте отдельную пустую учебную БД и откройте Query Tool именно для неё.
Последовательно выполните файлы целиком:

1. [sql/schema.sql](sql/schema.sql) — таблицы и ограничения.
2. [sql/seed.sql](sql/seed.sql) — синтетические данные.
3. [sql/checks.sql](sql/checks.sql) — четыре ожидаемых нарушения, изменения откатываются.
4. [sql/queries.sql](sql/queries.sql) — восемь аналитических запросов; можно запускать по одному.

Сравните ответы с [results/queries](results/queries/).
Повторно schema.sql и seed.sql в ту же БД не выполняются: для новой загрузки создайте другую БД.
