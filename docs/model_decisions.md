# Решения по учебной модели
1. Сохранены users, projects, columns, tasks; это новая модель, не миграция рабочей БД.
2. users хранит только идентификатор и уникальное имя. password_hash и авторизация исключены.
3. tasks.user_id — создатель: обе ветви создания исходного приложения записывают текущего пользователя; обновления board-service не меняют автора. Исполнитель теперь отдельный nullable FK assignee_id, а не имя/инициалы.
4. stat удалён: колонка определяет статус. is_done — новый явный признак конечного этапа, не зависит от переименования. Активная задача — любая задача в колонке is_done=false, включая очередь и проверку.
5. project_id и column_id обязательны; составной FK исключает колонку чужого проекта. UNIQUE(project_id,id) необходим как целевой ключ; id остаётся простым PK.
6. Номер положительный и уникален в проекте. Приоритет: low, medium, high; medium по умолчанию.
7. Исходный planned_date используется Гантом как начало. Он не переименован механически: в новой учебной БД выбран due_date — последний допустимый день выполнения. Это новая семантика на синтетических данных. Дедлайн среза ещё не просрочен; сравнение строго `< DATE '2026-11-12'`. Для NULL просрочка неизвестна.
8. Исходные недели и дни свёрнуты в planned_duration_days: положительные календарные дни, NULL если оценка отсутствует. В исходниках неделя = 7 дней; рабочий календарь не учитывается. Исходный ноль неоднозначен, поэтому в новой модели отсутствующая оценка — NULL. Фактическое время работы не измеряется.
9. board_state исключён: JSONB-снимок интерфейса дублирует реляционные данные. activity_log исключён: история событий не нужна базовым сценариям. Поэтому скорость выполнения, фактическая трудоёмкость и своевременность завершённых задач не рассчитываются.
10. Удалены client_id, позиции карточек, theme, customer_name, assignee_initials, tags и created_at: они не нужны выбранным учебным вопросам. Позиция этапа сохранена для порядка диаграмм. Отдельные справочники приоритетов и статусов не нужны.
11. Удаление автора, занятого проекта или колонки ограничено RESTRICT. Удаление исполнителя даёт SET NULL, сохраняя задачу; если пользователь одновременно автор, RESTRICT запретит удаление. Каскадного уничтожения задач нет. ON UPDATE — NO ACTION; идентификаторы считаются стабильными.
12. Индексы FK помогают проверкам удаления и соединениям. Индекс срока частичный; индексы по приоритету и is_done для 60 строк не оправданы. На таком объёме PostgreSQL может предпочесть последовательное сканирование.

Срез — 2026-11-12; синтетический набор трактуется как состояние на эту дату.
Доля завершения = завершённые / все задачи проекта; пустой проект — NULL.
Количество назначенных задач не является производительностью или фактической нагрузкой.
